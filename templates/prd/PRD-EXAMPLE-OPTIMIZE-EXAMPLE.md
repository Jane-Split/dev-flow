# PRD 示例 — 需求优化

> 本示例展示对"不合格品登记与处置管理"功能的优化需求如何填写 PRD 模板。
> 与"新需求示例"属于同一业务模块，优化内容为：新增审批撤回能力 + 列表查询增加发现人筛选 + 状态枚举新增"撤回中"。
> 产品经理可直接参考此示例的填写风格和详细程度。

---

## 一、需求概述

### 1.1 基本信息 【必填】

| 项目 | 内容 |
|------|------|
| **需求标题** | 不合格品审批增加撤回能力及列表优化 |
| **优先级** | P1(高) |
| **需求背景** | 质检员提交审批后发现信息有误，当前只能等质量主管驳回后才能修改，流程阻塞严重。需增加"撤回"操作，允许质检员在审批中状态下撤回已提交的审批。同时列表查询当前不支持按发现人筛选，质检员无法快速找到自己提交的记录。 |
| **目标用户** | 质检员、质量主管 |
| **期望上线时间** | 2026-07-20 |
| **关联原始需求** | 不合格品登记与处置管理（v1.0） |

### 1.2 影响范围 【必填】

| 项目 | 内容 |
|------|------|
| **涉及服务/模块** | quality-management（质量服务） |
| **跨服务交互** | 是。撤回审批需调用 workflow-service 取消审批实例 |
| **公共模块变更** | 是。NCPStatusEnum 新增"撤回中(5)"枚举值 |
| **数据库变更** | 仅新增数据（non_conforming_product 表新增 withdraw_remark 字段） |

## 二、功能点清单 【必填】

### 2.1 变更功能点列表

| # | 功能点名称 | 变更类型（新增/修改/删除） | 变更摘要 | 优先级 | 复杂度 |
|---|-----------|----------------------|---------|--------|--------|
| 1 | 审批撤回 | 新增 | 审批中状态下，质检员可撤回已提交的审批，状态回到待审批 | P1 | 中 |
| 2 | 不合格品列表查询 | 修改 | 新增"发现人"筛选条件 | P2 | 低 |

### 2.2 功能点变更说明 【必填】

#### 功能点 1：审批撤回

| 项目 | 内容 |
|------|------|
| **变更类型** | 新增 |
| **变更前行为** | 无撤回操作。审批中状态下，质检员只能等待质量主管审批或驳回。 |
| **变更后行为** | 审批中状态下，质检员（仅创建人本人）可点击"撤回"，填写撤回原因后，系统调用 workflow-service 取消审批实例，将状态从"审批中(1)"更新为"待审批(0)"，记录撤回原因和撤回时间。撤回后可修改信息并重新提交。 |
| **变更原因** | 解决质检员提交后发现信息有误但无法修改的问题，减少审批驳回导致的流程阻塞 |
| **涉及实体** | NonConformingProduct（新增 withdrawRemark、withdrawTime 字段） |
| **涉及接口** | POST /api/quality/non-conforming-products/{id}/withdraw（新增） |

#### 功能点 2：不合格品列表查询

| 项目 | 内容 |
|------|------|
| **变更类型** | 修改 |
| **变更前行为** | 列表查询支持 productId、batchNo、status、startTime、endTime 筛选，不支持按发现人筛选 |
| **变更后行为** | 列表查询新增 discovererId（发现人ID）筛选条件。传入时仅返回该发现人创建的记录。不传时行为不变。 |
| **变更原因** | 质检员需要快速筛选自己提交的记录，当前只能翻页查找 |
| **涉及实体** | 无变更 |
| **涉及接口** | GET /api/quality/non-conforming-products（修改查询参数） |

## 四、业务流程 【涉及流程变更时必填】

### 4.1 变更流程

#### 流程：审批撤回

| 步骤 | 角色 | 操作 | 变更类型 | 变更后逻辑 | 输出 | 异常处理 |
|------|------|------|---------|-----------|------|---------|
| 1 | 质检员 | 点击撤回 | 新增 | 前端弹出输入框，填写撤回原因 | 返回撤回确认页面 | - |
| 2 | 系统 | 处理撤回请求 | 新增 | 校验 status=1 + 创建人本人→调用 workflow-service.cancelProcess(instanceId)→更新 status=0, withdrawRemark, withdrawTime | 返回 200 | status≠1→400；非创建人→403；workflow 取消失败→降级处理 |
| 3 | 质检员 | 修改信息 | - | （不变）撤回后可正常编辑缺陷信息 | - | - |

#### 流程变更：原有"审批驳回→修改→重新提交"

| 步骤 | 角色 | 操作 | 变更类型 | 变更后逻辑 | 输出 | 异常处理 |
|------|------|------|---------|-----------|------|---------|
| 1 | 质量主管 | 驳回 | - | （不变）status 1→3 | - | - |
| 2 | 质检员 | 修改缺陷描述 | - | （不变） | - | - |
| 3 | 质检员 | 重新提交审批 | - | （不变） | - | - |

> 注：驳回→修改→重新提交流程无变更，仅新增撤回路径。

### 4.2 状态机变更 【条件必填】

**新增的状态流转**：

```
[审批中(1)] ──撤回──→ [待审批(0)]    (新增)
```

| 当前状态 | 操作 | 目标状态 | 变更类型 | 前置条件 | 触发后系统行为 |
|----------|------|---------|---------|---------|--------------|
| 1(审批中) | 撤回 | 0(待审批) | 新增 | 仅创建人本人可操作 + workflow cancel 成功 | 调用 workflow-service.cancelProcess()，记录撤回原因和时间，通知质量主管 |

**禁止操作变更**：

| 当前状态 | 禁止操作 | 变更类型 | 系统行为 |
|----------|---------|---------|---------|
| 1(审批中) | 非创建人撤回 | 新增 | 返回 403 FORBIDDEN "仅创建人可撤回" |
| 1(审批中) | 撤回原因为空 | 新增 | 返回 400 WITHDRAW_REASON_REQUIRED "撤回原因不能为空" |

## 五、业务规则 【必填】

### 5.1 校验规则变更

| # | 规则名称 | 变更类型 | 校验对象 | 校验条件 | 不满足时行为 | 错误码 | 错误信息 |
|---|---------|---------|---------|---------|-------------|--------|---------|
| 1 | 撤回原因非空 | 新增 | withdrawRemark | 撤回时必填，不超过 500 字符 | 返回 400 | WITHDRAW_REASON_REQUIRED | "撤回原因不能为空" |

### 5.2 业务规则变更

| # | 规则名称 | 变更类型 | 触发场景 | 条件（IF） | 行为（THEN） | 否则行为（ELSE） |
|---|---------|---------|---------|-----------|-------------|----------------|
| 1 | 仅创建人可撤回 | 新增 | 撤回审批 | 当前登录用户 ID ≠ 记录的 discovererId | 返回 403 FORBIDDEN "仅创建人可撤回" | 允许撤回 |
| 2 | 撤回后状态重置 | 新增 | 撤回成功 | workflow-service.cancelProcess() 返回成功 | status→0，记录 withdrawRemark 和 withdrawTime | 不更新状态 |
| 3 | workflow 取消失败处理 | 新增 | 撤回时 workflow 服务返回失败 | cancelProcess() 调用失败或超时 | 返回 500 WITHDRAW_FAILED "撤回失败，请稍后重试"，status 不变 | 正常撤回 |

### 5.3 被删除的规则

无删除的规则。

| # | 异常场景 | 触发条件 | 期望系统行为 | HTTP 状态码 | 错误码 |
|---|---------|---------|-------------|-----------|--------|

|---|----------|----------------------|-----------|------|---------|
| 1 | 撤回审批 | 新增 | POST | /api/quality/non-conforming-products/{id}/withdraw | 新增撤回接口 |

### 7.2 接口变更定义

#### 接口 1：撤回审批

**变更类型**：新增

**请求体**：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|---------|------|
| withdrawRemark | String | 是 | @NotBlank, @Size(max=500) | 撤回原因 |

**成功响应** (200)：

```json
{
  "code": 0,
  "message": "撤回成功"
}
```

**错误响应**：

| 场景 | HTTP 状态码 | code | message |
|------|-----------|------|---------|
| 记录不存在 | 404 | RESOURCE_NOT_FOUND | "不合格品记录不存在" |
| 非审批中状态 | 400 | STATUS_NOT_ALLOWED | "仅审批中的记录可以撤回" |
| 非创建人 | 403 | FORBIDDEN | "仅创建人可撤回" |
| 撤回原因为空 | 400 | WITHDRAW_REASON_REQUIRED | "撤回原因不能为空" |
| workflow 取消失败 | 500 | WITHDRAW_FAILED | "撤回失败，请稍后重试" |

#### 接口 2：列表查询

**变更类型**：修改（新增查询参数）

**新增查询参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| discovererId | Long | 否 | 发现人ID筛选，传入时仅返回该发现人创建的记录 |

**成功响应** (200)：与原接口响应格式一致，无变更。

### 7.3 兼容性影响

|--------|-------------|-------------------|

| 列表查询新增参数 | 无影响（可选参数，不传时行为不变） | 否 |
