# PRD 模板 — 新需求

> 适用范围：**新需求**（含新建数据库表、全新业务模块）
>
> 填写规则：`【必填】` 必须填写 · `【条件必填】` 触发条件满足时填写 · `【建议】` 选填可提升质量
> 不删除任何章节标题，无内容时填"无"。

---

## 一、需求概述

### 1.1 基本信息 【必填】

| 项目 | 内容 |
|------|------|
| **需求标题** | 一句话描述，不超过 30 字 |
| **优先级** | P0(紧急) / P1(高) / P2(中) / P3(低) |
| **需求背景** | 为什么要做？解决什么业务问题？（2-5 句） |
| **目标用户** | 谁会使用？列出所有角色 |
| **期望上线时间** | YYYY-MM-DD |

### 1.2 影响范围 【必填】

| 项目 | 内容 |
|------|------|
| **涉及服务/模块** | 列出所有受影响的服务或模块 |
| **跨服务交互** | 是否需要调用其他服务的接口？ |
| **公共模块变更** | 是否需要在公共模块中新增 DTO/Enum？ |
| **数据库变更** | 新建表 / 修改表结构 / 仅新增数据 / 无变更 |

## 附录：自检清单 【必填】

> 提交前逐项自检，全部通过后再交给开发。

### 准确性（无歧义）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| A1 | 功能点输入/输出 | 具体到字段级别，无"信息"等模糊词 |
| A2 | 数据模型字段 | 类型明确、校验规则清晰 |
| A3 | 业务规则格式 | 使用"如果...则...否则..."格式 |
| A4 | 状态机完整性 | 所有状态和转换路径已定义 |
| A5 | 验收标准可验证 | 无"功能正常""体验良好"等主观描述 |

### 完整性（无遗漏）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| B1 | 异常场景 | 每个功能点至少 2 个异常场景 |
| B2 | 枚举值 | 所有枚举值含义和规则已定义 |
| B3 | 写接口幂等性 | 每个写接口定义了重复提交行为 |
| B4 | 跨服务降级 | 每个跨服务调用定义了失败策略 |

### 一致性（无矛盾）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| C1 | 状态机无矛盾 | 无互斥的状态转换 |
| C2 | 业务规则无矛盾 | 无规则互相冲突 |
| C3 | 验收标准与规则一致 | 期望行为与规则定义不冲突 |

### 逻辑性（无遗漏路径）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| D1 | 流程步骤异常处理 | 每步的"异常处理"列已填写 |
| D2 | 禁止操作矩阵 | 每个状态都有禁止操作定义 |
| D3 | 边界场景 | 有边界值的字段都有边界测试 |
| D4 | 错误码唯一 | 同一错误码不对应多个场景 |
