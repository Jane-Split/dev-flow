# PRD 模板 — 需求优化

> 适用范围：**需求优化**（已有功能的改进、增强、调整）
>
> 填写规则：`【必填】` 必须填写 · `【条件必填】` 触发条件满足时填写 · `【建议】` 选填可提升质量
> 不删除任何章节标题，无内容时填"无"。

---

## 一、需求概述

### 1.1 基本信息 【必填】

| 项目 | 内容 |
|------|------|
| **需求标题** | 一句话描述，不超过 30 字 |
| **优先级** | P0(紧急) / P1(高) / P2(中) / P3(低) |
| **需求背景** | 为什么需要优化？当前有什么问题？（2-5 句） |
| **目标用户** | 本次优化影响哪些角色 |
| **期望上线时间** | YYYY-MM-DD |
| **关联原始需求** | 优化所基于的原始需求名称/文档 |

### 1.2 影响范围 【必填】

| 项目 | 内容 |
|------|------|
| **涉及服务/模块** | 列出所有受影响的服务或模块 |
| **跨服务交互** | 是否需要调用其他服务的接口？ |
| **公共模块变更** | 是否需要在公共模块中新增 DTO/Enum？ |
| **数据库变更** | 修改表结构 / 仅新增数据 / 无变更 |

### 章节填写范围

> 不涉及变更的章节填"无"，涉及变更的章节仅需填写变更部分。

| 章节 | 填写规则 |
|------|---------|
| 一、需求概述 | 必填 |
| 二、功能点清单 | 必填（仅变更的功能点） |
| 三、数据模型 | 涉及表变更时必填（仅变更字段） |
| 四、业务流程 | 涉及流程变更时必填（仅变更步骤） |
| 五、业务规则 | 必填（仅变更/新增的规则） |
| 六、异常场景 | 必填（仅新增的异常场景） |
| 七、API 交互 | 涉及接口变更时必填（仅变更接口） |
| 八、非功能需求 | 建议 |
| 九、验收标准 | 必填（新增场景 + 回归验证） |
| 十、补充信息 | 选填 |
| 附录 A 自检清单 | 必填 |
| 附录 B 变更差异对比 | 必填 |

## 附录 A：自检清单 【必填】

> 提交前逐项自检，全部通过后再交给开发。

### 准确性（无歧义）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| A1 | 变更前后对比 | 每个变更项都有明确的"变更前"和"变更后" |
| A2 | 数据模型变更 | 类型明确、校验规则清晰、变更标记正确 |
| A3 | 业务规则格式 | 使用"如果...则...否则..."格式 |
| A4 | 验收标准可验证 | 无"功能正常""体验良好"等主观描述 |
| A5 | 接口兼容性 | 修改的接口已评估兼容性影响 |

### 完整性（无遗漏）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| B1 | 回归范围 | §9.2 回归验证覆盖了所有受影响的已有功能 |
| B2 | 删除影响 | 删除的功能/规则/接口已评估影响 |
| B3 | 兼容性 | 跨服务接口变更已标注是否需要调用方改造 |
| B4 | 数据迁移 | 表结构变更已说明数据迁移方案（如需要） |

### 一致性（无矛盾）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| C1 | 变更与原有规则不冲突 | 新规则不与未变更的已有规则矛盾 |
| C2 | 状态机无矛盾 | 新增的状态转换不与已有转换冲突 |
| C3 | 验收标准与变更一致 | 期望行为与变更定义不冲突 |

### 逻辑性（无遗漏路径）

| # | 检查项 | 通过标准 |
|---|--------|---------|
| D1 | 变更流程异常处理 | 变更的流程步骤有异常处理 |
| D2 | 边界场景 | 变更涉及的边界值有测试覆盖 |
| D3 | 错误码唯一 | 新增错误码不与已有错误码重复 |
